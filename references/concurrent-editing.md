# 并发保护前提与锁域边界

> SPEC《2026-09-29 agent-fs 可靠编辑》§3.2 的落地细则。本文件回答两个问题：
> 什么时候并发保护成立、什么时候**不**成立。

## 同一锁域（互斥成立的前提）

"同一锁域"要求参与者**同时满足**以下三条，缺一不可：

1. 同一 `AGENT_FS_HOME` 所确定的锁目录（未设置时为 `~/.agent-fs/locks/`）；
2. 同一规范化目标路径（`path.resolve()` 后一致；硬链接、大小写别名、
   不同挂载别名未统一时不构成同一锁域）；
3. 兼容的锁实现（POSIX `flock` / Windows `msvcrt.locking`，非阻塞独占）。

仅仅都调用名为 agent-fs 的程序，**不构成**同一锁域。

## 场景与保证边界

| 场景 | 执行方式 | 保证边界 |
|---|---|---|
| 多个 AI 并行修改 Git 项目 | 写任务进入各自 worktree（`using-git-worktrees`），由单一集成者合并 | 保存各自成果，语义冲突仍需解决 |
| 同一本地文件的多个受控写入 | 一致目标路径、同一锁域、同一校验与写入协议 | 串行校验并提交，旧基线被拒绝（`hash_mismatch`/`lock_busy`） |
| 人工编辑器或普通 Shell 并发写入 | 写前复核、写后比较；必要时停止该文件的共享写入 | **不承诺**任意外部进程的严格互斥——外部写入不获取协作锁 |
| 不同机器访问共享文件 | 使用该资源已有协调机制，或停止共享写入 | 本机默认锁不能承担跨机器协调 |

## 其他边界

- 首期针对本地普通文件。最终路径为符号链接时拒绝（`final_path_is_symlink`）；
  调用方显式 `resolve()` 后传入物理路径才能重新操作。
- 任务编排应传递一致的绝对路径；传相对路径的多个调用方可能解析到不同目标。
- 目录内的其他文件及工作区外部资源不因 worktree 而自动隔离。
- 单文件原子替换不等于多文件原子提交；批量任务逐文件记录和恢复。
- 后续覆盖仍需重新校验：其他写入者在锁释放后再修改文件，不会使此前的
  `verified` 观察变成永久保证。

## 验收对照（SPEC §11）

- A01：A 读原文，B 完成修改，A 再写 → A 返回 `rejected`，B 的完整内容保留。
- A02：两个进程持相同旧基线同时写 → 同锁域内至多一个提交；另一个锁忙或基线冲突，无混合内容。
- A19：非协作写入、不同锁域或跨机器 → 行为与文档不宣称全局互斥；
  不同 `AGENT_FS_HOME` 的两个写入互不感知（可各自成功），以此证明锁域边界真实存在。
